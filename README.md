# phriend-web

Marketing site for Phriend, a local-services marketplace in the Philippines where clients book services from verified providers: aircon cleaning and repair, bookkeeping and tax filing, tutoring, photo and video, driving, errands and more, each priced per job, hour or session. Live at [phriend.app](https://phriend.app).

## Part of Phriend

| Repo | What it is |
|---|---|
| phriend-web | Marketing site (phriend.app). This repo. |
| phriend-ui | Shared design tokens and web components, synced into the apps |
| phriend-ph | Next.js PWA (web.phriend.app) |
| phriend-api2 | Platform v2 API (api2.phriend.app); its public `/v1` routes feed this site through the synced contracts client in `lib/phriend2/` |
| phriend-admin | Ops moderation portal |
| phriend-expo | Android/iOS app |
| provider.phriend.app | Provider site (Phriend Provider) |

## What's on the site

- Landing page (`/`)
- Services (`/services`, `/services/[group or category]`), city pages and category-in-city pages (`/[slug]`, e.g. `/manila`, `/aircon-cleaning-in-manila`), and occasions (`/occasions`, `/occasions/[occasion]`), all read from api2 with ISR
- Creators (`/creators`) and a creator card endpoint (`/creators/card`)
- Teams (`/teams`, a 404 while the client app has teams off), Get the app (`/download`; `/android` redirects there), Press (`/press`)
- Blog (`/blog`, `/blog/[slug]`): the coded posts in `app/blog/_posts`; Ops articles arrive with `GET /v1/content/blog` (W3)
- Safety, community guidelines, privacy, terms, delete-account
- `sitemap.xml`, `robots.txt`, web manifest, generated Open Graph images
- `llms.txt` and `llms-full.txt` (plain-text descriptions for LLM crawlers), in `public/`

## Tech stack

- Next.js 16 (App Router), React 19, TypeScript
- Tailwind CSS 4
- lucide-react, zod (the contracts client)
- Google Analytics through `next/script` (optional, off when `NEXT_PUBLIC_GA_ID` is unset)

## Getting started

Requires Node.js and npm.

```bash
npm install
npm run dev:v2
```

`dev:v2` runs the site at http://localhost:3110 against the local api2 at http://localhost:8040 (start api2 with the stack; it is not started here). It refuses an `API_URL` that is not a loopback address.

Environment variables:

| Name | Purpose |
|---|---|
| `API_URL` | **Required.** Base URL of api2 (no trailing `/v1`). There is no default: the server throws, and a production build fails, when it is unset, so a local run never reads production. The site reads public routes only; no server key or BFF secret. |
| `NEXT_PUBLIC_GA_ID` | Google Analytics measurement ID. Analytics scripts are not loaded when unset. |

When api2 does not answer, the pages still render: lists show "Services are loading. Browse them in the app." and ISR fills them on the next revalidation.

## Scripts

| Command | Description |
|---|---|
| `npm run dev:v2` | Start the dev server on port 3110 against api2 on :8040 |
| `npm run dev` | Start the dev server on port 3100 (set `API_URL` yourself) |
| `npm run build` | Production build |
| `npm run start` | Serve the production build |
| `npm run lint` | Run ESLint |
| `npm test` | Node tests in `lib/*.test.mjs` (copy rules, link parsing, the off-product filter) |

## Project layout

```
app/          Routes, layout, sitemap, robots, manifest, OG images
components/   Page and UI components (ui.tsx is generated from phriend-ui)
lib/          Site constants, api2 access (api.ts, catalogue.ts), links, landing copy, occasions, creator card
lib/phriend2/ Generated by phriend-api2 contracts/sync.mjs; never edit here
public/       Static files, llms.txt, llms-full.txt
scripts/      dev:v2 launcher, CDN upload
```

`app/phriend-ui.css` and `components/ui.tsx` are generated by phriend-ui; change them there, not here.

## Deployment

A standard Next.js app (`next build --webpack`, `next start`), deployed as a Hostinger Node.js web app that rebuilds on every push to `main`.
